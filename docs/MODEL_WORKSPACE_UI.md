# Research workspace

The seven top-level pages remain. Restart `run_simulation.py` to load the updated interface.

## Model

- **Model library:** inspect M0 and published, training-eligible adaptation models. Retired M1 stays outside the library. Component values are read from the selected model. “Use for new PPO setup” stages the selection and opens PPO settings; it never starts training or rewrites a saved policy.
- **Fit model:** choose a reviewed free-flight batch and click **Fit drone + cable model**. A separate job runs preparation, drone fitting, cable fitting, attitude refinement, baseline evaluation and combined validation sequentially. The model-library shortcut opens this tab. Readiness shows the paired-take count; five pairs are required by the current protocol. Individual stages are available under a collapsed advanced control. Opening the page does no work.
- **Fit evidence:** load historical M0 diagnostics or saved adaptation-fit comparisons. These are distinct from real-flight performance.
- **Workflow:** navigation between recordings, flight comparison, fitting, PPO and rehearsal.

The fit runner deliberately retains the existing bounded protocol: exactly five paired flights executing the original M0 CSV, known clock alignment, M0 differentiable fitting seed, one-second whip and the existing fit weights. It rejects other CSVs rather than silently applying hard-coded old timing/target assumptions. It is not a general M1-to-M2 workflow. Stage prerequisites and completed-stage checks protect saved results. A stop request is honored at an update/stage boundary; a long solver operation may need to finish first. Partial results remain on disk. No automatic publishing, global model replacement or training follows fitting.

## Recordings

**Current flight batches** lists policy-scoped raw pairs, timing status and source. The reviewed offset editor saves `time_alignment.json`, bound to exact raw file hashes. Measured state comes from OptiTrack; controller logs provide commands and timing. “Compare flight in 3D” selects that pair in Adaptation Check; click Load flight there. Historical processing and legacy tools are explicitly separated. Raw data is never edited by this page.

## PPO and export

PPO keeps Training, Policies, Task & rewards and Multi-drone scene. New-run settings scroll in a bounded panel so they do not push the monitoring area off-screen. Rehearsal has compact XYZ fields and a scrollable control panel. Its initial policy selection prefers the retained flown `20260908-195207-486249-seed655/best_validation.pt`; refresh preserves a user's later selection. Original CSVs are not regenerated by opening the page.

MPPI remains independent and paused. Its header reads the actual configured model, replacing a stale hard-coded M1 label. Historical Diagnostics are labeled as such. Adaptation Check preserves exact CSV-matched ghosts and separates measured flight progress from fitted-model diagnostics.

The current single drone is detected automatically from its OptiTrack pose name; the identity editor only appears when multiple candidates require selection. Current hardware mass is separately recorded in `config/current_vehicle.json`: 153 g drone plus unchanged 18 g cable. Model library shows that observation alongside the saved model mass. Historical M0 and its original flight CSV retain their original configuration for the repeat-flight comparison.
