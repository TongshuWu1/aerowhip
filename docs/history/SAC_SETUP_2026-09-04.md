# SAC setup

SAC is configured as a fresh comparison with PPO, without copying PPO weights.
Task, force bounds, reward and uncertainty settings remain shared through
`config/model.json`, `config/task.json` and `config/ppo.json`.

The policy sees the 79-dimensional observation from a private nominal model,
initialized from one state estimate. Planning stops at its first predicted valid
hit; commands are frozen, executed once on a separate perturbed plant, and
followed by PID recovery. Actual strike feedback does not enter the policy or
alter the cutoff. Plans with no predicted hit are refused.

The SAC critics additionally receive the initial estimate and the earlier
planned actions. This training-only history is needed to value the eventual
execution outcome; it contains neither future actions nor plant feedback.
Replay stores planning transitions with the complete attempt/recovery reward
on the last transition. Gamma is 1, so the only explicit strike-time cost is
the shared **1 point/second**. The existing 10-point recovery-failure cost and
5 cm / 4 m/s / 45-degree hit gate remain in effect.

## Training settings

| Setting | Value |
| --- | --- |
| Actor inputs / stochastic force axes | 79 / Fx, Fz (Fy = 0) |
| Actor and critic hidden layers | 256, 256 |
| Parallel collection | 1,024 episodes |
| Replay capacity / minibatch | 262,144 / 1,024 transitions |
| SAC updates per collection | 64 |
| Initial random exploration | 16,384 transitions, rounded to a collection |
| Actor / critic / temperature learning rate | 1e-4 / 3e-4 / 1e-4 |
| Gamma / target smoothing | 1.0 / 0.005 |
| Initial entropy temperature | 0.2, learned automatically |
| Validation | 256 fixed-seed trials every 8,192 episodes |

The best checkpoint is ranked by hit plus recovery, hit rate, executable-plan
rate, then reward. SAC continues learning off-policy without PPO-style update
rollback; its best validated checkpoint is kept separately from the latest
optimizer state. The uncertainty ranges are provisional simulation assumptions,
not measured hardware distributions.

## Use

In **SAC Training**, use **TRAIN FROM SCRATCH**, **STOP SAFELY**, or choose a
saved run and **CONTINUE SELECTED**. The episode input specifies additional
episodes when continuing. Checkpoints include actor, critics, target critics,
temperature, optimizers, architecture and random-generator states. Continuation
refills its replay buffer with new experience; it is not an exact replay-buffer
resume. Legacy feedback-trained SAC checkpoints cannot continue in this mode.

Choose **USE IN RUN & REPLAY** to load the selected SAC checkpoint into live
one-shot mode. Start flight, wait for hover readiness, then click **STRIKE**.
Fresh policies generally cannot predict a valid strike yet and stay in hover.

```powershell
.\.venv\Scripts\python.exe run_sac.py --preflight --device cuda
.\.venv\Scripts\python.exe run_sac.py --train --device cuda --episodes 32768 --batch 1024
```

Previous exploratory runs and checkpoints were deleted on 2026-09-05 at the
user's request. New paper experiments must start from fresh initialization.
See [the paper experiment protocol](../PAPER_EXPERIMENT_PROTOCOL.md) for the
proposed evaluation, logging and plotting requirements. Passing preflight
establishes that collection and optimization execute; it does not measure
learned strike performance.
